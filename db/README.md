# Database (`db/`)

| File | Purpose |
| --- | --- |
| `simple.sql` | Schema: 7 raw telemetry tables |
| `seed.sql` | Test dataset (deterministic, consistent across all tables) |
| `generate_seed.py` | Regenerates `seed.sql` (`python generate_seed.py seed.sql`, standard library only) |

## Load (local PostgreSQL)
```bash
psql -U <user> -d <db> -f db/simple.sql      # only once, creates the tables
psql -U <user> -d <db> -f db/seed.sql        # safe to re-run
```
`seed.sql` starts with a `TRUNCATE` of all 7 tables, so re-running gives you a clean dataset
(and **deletes anything already in those tables**). `employee_id` is generated by the table, so the seed works with an
identity/serial or default-generated key.

## What the data represents
"Today" is **Sun 2026-10-25**. The scheduler's latest fetch ran **Fri 2026-10-23**.

| Source | Fetches in the seed |
| --- | --- |
| Copilot user detail / trend / summary | `D30` snapshots on 2026-08-28, 2026-09-25, 2026-10-23 |
| Claude usage / cost | `D7` fetch every Friday, 2026-08-07 to 2026-10-23 (usage dates 2026-07-31 to 2026-10-22) |
| ChatGPT usage / cost | `D7` fetch every Friday, 2026-08-07 to 2026-10-23 (usage dates 2026-07-31 to 2026-10-22) |

It all comes from one simulated day-by-day activity log, so the tables agree with each other:
- Copilot detail per user = totals over that snapshot's 30-day window; the trend and summary rows are counted from the same daily activity (prompts, active users and app counts reconcile exactly).
- Claude cost = tokens x published per-model prices (Sonnet 4.5 $3/$15, Opus 4.1 $15/$75, Haiku 4.5 $1/$5 per million input/output; cache read/creation at their own rates). Every usage row has exactly one cost row.
- ChatGPT cost = tokens x published per-model prices (gpt-5 $1.25/$10.00/$0.125, gpt-4.1 $2.00/$8.00/$0.50, gpt-4o $2.50/$10.00/$1.25, gpt-4o-mini $0.15/$0.60/$0.075 per million input/output/cached). Every usage row has exactly one cost row.
- Token volumes are scaled so users spread across the dashboard's Claude and ChatGPT segments.

## Data model notes
- `report_period` holds the rolling-window label (`D7`, `D30`), not a calendar month. The API turns `2026-10` into a date range and filters on `usage_date`, `cost_date` and `report_refresh_date`.
- Weekly view = latest fetch only (`snapshot_fetched_at` for Copilot, `report_refresh_date` for Claude/ChatGPT).
